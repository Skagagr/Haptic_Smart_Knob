## 1. 模块概述

### 1.1 解决的问题

旋钮有 3 种"控制模式"：

| 模式 | 旋钮转动的作用 |
|------|--------------|
| **空闲** | 纯力反馈手感，不调节任何系统参数 |
| **控制音量** | 转旋钮 → 电脑音量 ±1% |
| **控制亮度** | 转旋钮 → 电脑亮度 ±1% |

需要：硬件按钮切换模式、LED 显示当前模式、状态可被上位机读取/设置。

### 1.2 两个模块的分工

| 模块 | 层次 | 职责 |
|------|------|------|
| `app_mode` | App 层 | 模式状态、按钮**业务逻辑**（按什么键切到什么模式） |
| `bsp_knob_indicator` | BSP 层 | 硬件：LED 点亮/熄灭、按键**扫描**（消抖+边沿检测） |

**解耦原则**：BSP 层只关心"哪个引脚被按下"，返回事件；App 层决定
"这个事件对应什么动作"。加新按键只改 BSP，加新模式只改 App。

## 3. 控制模式状态

### 3.1 模式枚举（`app_mode.h`）

```c
typedef enum
{
    KNOB_STATE_MODE_IDLE = 0,       // 空闲（不控制音量/亮度）
    KNOB_STATE_MODE_VOLUME,         // 控制音量
    KNOB_STATE_MODE_BRIGHTNESS,     // 控制亮度
} KnobStateMode_t;
```

**值约定**：与上位机 `KnobControlMode` 枚举**逐值对齐**
（IDLE=0/VOLUME=1/BRIGHTNESS=2），这样协议里直接传字节即可，
两边不用做映射转换。

### 3.2 状态变量

```c
static KnobStateMode_t s_mode;   // 当前控制模式
```

### 3.3 三个核心接口

```c
KnobStateMode_t AppMode_GetMode(void);   // 读模式（协议 GET_STATE 上报用）
void AppMode_SetMode(KnobStateMode_t mode);  // 设模式（上位机 SET_MODE 同步用）
void AppMode_NextMode(void);             // 切下一状态（按钮用）
```

**`AppMode_SetMode` 的越界保护：**

```c
void AppMode_SetMode(KnobStateMode_t mode)
{
    if (mode > KNOB_STATE_MODE_BRIGHTNESS)   // 协议/上位机可能传越界数据
    {
        mode = KNOB_STATE_MODE_IDLE;
    }
    s_mode = mode;
    BSP_KnobIndicator_SetMode(s_mode);       // 模式变化 → 更新 LED
}
```

**为什么钳制**：USB 协议层收到 `SET_MODE` 时只校验了 `len`，
模式值来自上位机，可能越界。这里兜底，避免 LED switch 走进 default 全灭。

### 3.4 循环切换

```c
void AppMode_NextMode(void)
{
    switch (s_mode)
    {
        case KNOB_STATE_MODE_IDLE:      AppMode_SetMode(KNOB_STATE_MODE_VOLUME);     break;
        case KNOB_STATE_MODE_VOLUME:    AppMode_SetMode(KNOB_STATE_MODE_BRIGHTNESS); break;
        case KNOB_STATE_MODE_BRIGHTNESS:
        default:                        AppMode_SetMode(KNOB_STATE_MODE_IDLE);       break;
    }
}
```

空闲 → 音量 → 亮度 → 空闲，循环切换。

## 4. 指示灯驱动

### 4.1 硬件

3 个独立 LED，**低电平点亮**（拉高熄灭）：

| 模式 | 引脚 |
|------|------|
| 空闲 | PA2 |
| 控制音量 | PA3 |
| 控制亮度 | PA4 |

### 4.2 引脚定义（`bsp_knob_indicator.h`）

```c
#define KNOB_LED_IDLE_PORT       GPIOA
#define KNOB_LED_IDLE_PIN        GPIO_PIN_2
#define KNOB_LED_VOLUME_PORT     GPIOA
#define KNOB_LED_VOLUME_PIN      GPIO_PIN_3
#define KNOB_LED_BRIGHTNESS_PORT GPIOA
#define KNOB_LED_BRIGHTNESS_PIN  GPIO_PIN_4
```

### 4.3 点亮逻辑（保证只有一盏亮）

```c
void BSP_KnobIndicator_SetMode(KnobStateMode_t mode)
{
    // 先全部熄灭（拉高）
    HAL_GPIO_WritePin(KNOB_LED_IDLE_PORT,       KNOB_LED_IDLE_PIN,       GPIO_PIN_SET);
    HAL_GPIO_WritePin(KNOB_LED_VOLUME_PORT,     KNOB_LED_VOLUME_PIN,     GPIO_PIN_SET);
    HAL_GPIO_WritePin(KNOB_LED_BRIGHTNESS_PORT, KNOB_LED_BRIGHTNESS_PIN, GPIO_PIN_SET);

    switch (mode)
    {
        case KNOB_STATE_MODE_IDLE:
            HAL_GPIO_WritePin(KNOB_LED_IDLE_PORT, KNOB_LED_IDLE_PIN, GPIO_PIN_RESET);   // 拉低点亮
            break;
        case KNOB_STATE_MODE_VOLUME:
            HAL_GPIO_WritePin(KNOB_LED_VOLUME_PORT, KNOB_LED_VOLUME_PIN, GPIO_PIN_RESET);
            break;
        case KNOB_STATE_MODE_BRIGHTNESS:
            HAL_GPIO_WritePin(KNOB_LED_BRIGHTNESS_PORT, KNOB_LED_BRIGHTNESS_PIN, GPIO_PIN_RESET);
            break;
        default:
            break;   // 全灭
    }
}
```

**先全灭再点亮**：保证任意时刻**恰好一盏灯亮**，切换时不会两盏同时亮。

## 5. 按键扫描

### 5.1 硬件

2 个按键，**按下=低电平**（上拉输入）：

| 按键 | 引脚 | 作用 |
|------|------|------|
| PB12 | 回空闲 | 按下直接切到空闲模式 |
| PB13 | 切下一状态 | 按下循环切：空闲→音量→亮度 |

### 5.2 事件枚举（`bsp_knob_indicator.h`）

```c
typedef enum
{
    KNOB_BTN_EVENT_NONE = 0,   // 无事件
    KNOB_BTN_EVENT_BACK,       // PB12 按下（回空闲）
    KNOB_BTN_EVENT_NEXT,       // PB13 按下（切下一状态）
} KnobBtnEvent_t;
```

### 5.3 扫描流程（消抖 + 边沿检测）

```
BSP_KnobButton_Scan()
  │
  ├─ 1. 限流：距上次扫描 < 20ms → 返回无事件（跳过抖动窗口）
  │
  ├─ 2. 边沿检测（对每个按键）：
  │      读当前电平 cur
  │      仅当"当前=按下(RESET) 且 上次=未按下(SET)" → 上报按下事件
  │      更新"上次电平"记录
  │
  └─ 3. 返回检测到的事件
```

### 5.4 边沿检测为什么必要

如果"只要读到低电平就触发"，用户**按住 1 秒**会触发 50 次
（20ms × 50 = 1s）。加上"从高变低"的边沿判断后：

- 只有**按下的那一瞬间**触发一次
- 按住不放不重复触发
- 必须先松开再按，才再触发

### 5.5 关键代码

```c
#define KNOB_BTN_SCAN_INTERVAL  20   // 两次扫描最小间隔 (ms)

static KnobBtnEvent_t CheckButtonEdge(GPIO_TypeDef *port, uint16_t pin,
                                      GPIO_PinState *last_state, KnobBtnEvent_t event)
{
    GPIO_PinState cur = HAL_GPIO_ReadPin(port, pin);

    // 先更新"上一次状态"，再判断是否触发（保证按住不重复触发）
    if (cur == GPIO_PIN_RESET && *last_state == GPIO_PIN_SET)
    {
        *last_state = cur;
        return event;
    }
    *last_state = cur;
    return KNOB_BTN_EVENT_NONE;
}

KnobBtnEvent_t BSP_KnobButton_Scan(void)
{
    uint32_t now_tick = HAL_GetTick();

    // 限流：没到 20ms 直接返回（跳过机械抖动窗口）
    if (now_tick - s_last_tick < KNOB_BTN_SCAN_INTERVAL)
        return KNOB_BTN_EVENT_NONE;
    s_last_tick = now_tick;

    // 依次检查两个按键
    KnobBtnEvent_t ev = CheckButtonEdge(KNOB_BTN_BACK_PORT, KNOB_BTN_BACK_PIN,
                                        &s_last_back, KNOB_BTN_EVENT_BACK);
    if (ev != KNOB_BTN_EVENT_NONE) return ev;

    return CheckButtonEdge(KNOB_BTN_NEXT_PORT, KNOB_BTN_NEXT_PIN,
                           &s_last_next, KNOB_BTN_EVENT_NEXT);
}
```

**为什么用 `HAL_GetTick()` 限流而不是固定延时**：非阻塞。
函数每次调用立即返回，扫描频率由外部调用节奏决定（这里是 1kHz 循环），
内部用 tick 判断是否真到了 20ms。

## 6. 1kHz 集成

### 6.1 按键扫描放在 1kHz 控制循环

按键扫描在 `App_Knob_Control()` 的**第 8 步**调用：

```c
// app_knob.c 第 8 步
AppMode_ScanButtons();
```

**为什么不在主循环**：主循环有 `HAL_Delay(1000)` 会阻塞 1 秒，
按键扫描会被卡住（快速点按大概率错过）。放在 1kHz 中断里每 1ms 扫一次，
配合内部 20ms 限流，实时响应。

### 6.2 App 层按钮业务逻辑

```c
void AppMode_ScanButtons(void)
{
    KnobBtnEvent_t ev = BSP_KnobButton_Scan();
    switch (ev)
    {
        case KNOB_BTN_EVENT_BACK:
            AppMode_SetMode(KNOB_STATE_MODE_IDLE);   // PB12：回空闲
            break;
        case KNOB_BTN_EVENT_NEXT:
            AppMode_NextMode();                      // PB13：切下一状态
            break;
        default:
            break;
    }
}
```

**这里体现解耦**：`app_mode` 拿到的是"BACK/NEXT 事件"，不知道引脚是
PB12 还是 PB13——引脚映射在 BSP 层。以后换引脚、加按键，App 层不用动。

## 7. 与上位机的双向同步

控制模式是**双向同步**的：

```
① 下位机按钮切换 → 上位机读到
   按钮 → AppMode_NextMode → 状态变化
   → 上位机 50ms 轮询 GET_STATE → 响应 [模式+角度]
   → 上位机解析模式 → 同步 UI 复选框

② 上位机勾选 → 下位机切换 + 亮 LED
   上位机勾音量/亮度 → 发 SET_MODE
   → 固件 UsbProto_HandleSetMode → AppMode_SetMode
   → 状态变化 + 对应 LED 点亮
```

**协议交互**：

```
查询状态:  发 AA 55 07 00 [CRC]
          收 AA 55 87 06 00 [模式1B] [角度4B] [CRC]
设置模式:  发 AA 55 08 01 [模式] [CRC]
          收 AA 55 88 01 [状态] [CRC]
```

模式字节与上位机 `KnobControlMode` 对齐（0/1/2），无需转换。

```
系统上电
  └→ App_Knob_Init() → AppMode_Init()
       ├→ BSP_KnobIndicator_Init()   ← 熄灭 LED、清按键状态
       └→ AppMode_SetMode(IDLE)      ← 默认空闲，亮空闲 LED

--- 1kHz 控制循环（TIM3 ISR）---
App_Knob_Control()
  └→ 第 8 步: AppMode_ScanButtons()
       └→ BSP_KnobButton_Scan()      ← 20ms 限流 + 边沿检测
            └→ 返回 BACK/NEXT 事件
       └→ 切模式 → AppMode_SetMode
            └→ BSP_KnobIndicator_SetMode()  ← 点亮对应 LED

--- PC 同步（USB 中断）---
SET_MODE  → AppMode_SetMode() → 亮 LED
GET_STATE → AppMode_GetMode() → 随角度一并上报
```
