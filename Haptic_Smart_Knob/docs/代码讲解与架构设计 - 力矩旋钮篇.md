## 1. 系统概述

### 1.1 项目目标

在 STM32F103C8T6 上实现一个**力反馈旋钮**：旋转旋钮时，电机施加力矩，模拟出"一格一格"的卡位手感（类似鼠标滚轮）。

### 1.2 实现的功能

| 功能 | 说明 |
|------|------|
| 卡位手感 | 转动时有"爬坡-释放"的棘轮阻力 |
| 松手归中 | 停止转动 20ms 后，电机自动推向最近的卡位中心 |
| 角度限位 | 设置旋转范围，超出后弹簧推回 |
| 蜂鸣提示 | 跨过卡位或撞击限位时响一声 |
| 运行时调参 | 可在程序运行中切换预设方案和力度 |
| 蜂鸣器开关 | 上位机可远程开关蜂鸣（卡位/限位音效） |
| 控制模式 | 空闲/音量/亮度三态，按键切换 + LED 指示 |

> 控制模式（`app_mode`）与指示灯/按键（`bsp_knob_indicator`）详见
> 《代码讲解与架构设计 - 控制模式篇》；USB 通信协议详见
> 《代码讲解与架构设计 - USB通信协议篇》。

### 1.3 硬件组成

```
[旋钮] → [N20 减速电机] → [编码器] → STM32
                                  ↓
                            [TB6612 驱动] → 电机 PWM
                            [蜂鸣器] PB0
                            [LED×3]  PA2/PA3/PA4
                            [按键×2] PB12/PB13
```

- **编码器**：检测旋钮转动角度（TIM2 四倍频计数，2800 CPR）
- **电机**：N20 直流减速电机（100:1 减速比），通过 PWM 控制力矩
- **TB6612**：电机驱动芯片，控制方向和使能
- **蜂鸣器**：有源蜂鸣器，低电平触发
- **LED×3**：控制模式指示（空闲/音量/亮度），低电平点亮
- **按键×2**：切换控制模式（回空闲/切下一状态）

## 2. 硬件层

### 2.1 编码器驱动 (BSP_KnobEncoder)

```
文件：Drivers/BSP/Knob_Encoder/bsp_knob_encoder.c
```

**工作原理：**
- TIM2 配置为 Encoder Mode，自动对 A/B 相脉冲计数
- 7 PPR × 4 倍频 × 100 减速比 = 2800 个计数值/圈
- 角度换算：`angle = count / 2800.0f × 360.0f`

**关键接口：**
```c
void    BSP_KnobEncoder_Init(TIM_HandleTypeDef *htim);  // 启动编码器
int32_t BSP_KnobEncoder_GetRawCount(void);               // 读原始计数值
float   BSP_KnobEncoder_GetAngle(void);                   // 读角度 (°)
```

### 2.2 电机驱动 (BSP_KnobMotor)

```
文件：Drivers/BSP/Knob_Motor/bsp_knob_motor.c
```

**工作原理：**
- TIM4 CH1 输出 PWM（频率 = 72MHz / 1000 = 72kHz）
- PB7/PB8 控制 TB6612 的 AIN1/AIN2，决定方向
- PB9 控制 STBY（使能），必须拉高电机才会转

**方向控制：**

| 方向 | AIN1 (PB7) | AIN2 (PB8) | 效果 |
|------|-----------|-----------|------|
| FORWARD | 1 | 0 | 正转 |
| REVERSE | 0 | 1 | 反转 |
| BRAKE | 1 | 1 | 刹车（快速停止） |
| STOP | 0 | 0 | 自由滑行（无阻力） |

**关键接口：**
```c
void BSP_KnobMotor_Init(TIM_HandleTypeDef *htim);
void BSP_KnobMotor_SetOutput(Knob_Motor_Dir_t dir, uint8_t duty_pct);
```

### 2.3 蜂鸣器驱动 (BSP_KnobBuzzer)

```
文件：Drivers/BSP/Knob_Buzzer/bsp_knob_buzzer.c
```

**工作原理：**
- PB0 低电平时蜂鸣器响
- `Click()` 触发 5ms 脉冲（`BUZZER_ON_MS = 5`）
- 两次触发间有 50ms 冷却（`BUZZER_COOLDOWN = 50`），冷却期内 `Click()` 直接忽略，防止密集切换时连响
- `Tick()` 每 1ms 调用，管理脉冲计时（自动关断）

**关键接口：**
```c
void BSP_KnobBuzzer_Init(void);
void BSP_KnobBuzzer_Click(void);   // 触发短促蜂鸣
void BSP_KnobBuzzer_Tick(void);    // 1kHz 脉冲计时
```

## 3. 软件分层架构

### 3.1 分层图

```
┌──────────────────────────────────────────┐
│  main.c                                   │
│  - 系统初始化                              │
│  - 主循环中调用 App_Knob_Debug() 打印日志  │
└────────────┬─────────────────────────────┘
             │
┌────────────▼─────────────────────────────┐
│  App 层 (应用层)                          │
│                                           │
│  app_knob.c         ← 控制循环 + 状态机   │
│  app_knob_physics.c ← 卡位数学计算        │
│  app_knob_limit.c   ← 限位弹簧模拟        │
│  app_mode.c         ← 控制模式状态        │
└────────────┬─────────────────────────────┘
             │
┌────────────▼─────────────────────────────┐
│  BSP 层 (硬件抽象层)                      │
│                                           │
│  bsp_knob_encoder.c  ← 编码器读取         │
│  bsp_knob_motor.c    ← PWM + 方向控制     │
│  bsp_knob_buzzer.c   ← 蜂鸣器控制         │
│  bsp_knob_indicator.c← LED + 按键         │
└────────────┬─────────────────────────────┘
             │
┌────────────▼─────────────────────────────┐
│  HAL 层 (STM32 标准外设库)               │
│  TIM2/TIM3/TIM4, GPIO, USART, USB        │
└──────────────────────────────────────────┘
```

**分层原则：**
- **HAL 层**：STM32 官方库，由 CubeMX 生成，一般不修改
- **BSP 层**：封装硬件细节，提供简洁的函数接口
- **App 层**：实现旋钮的所有业务逻辑，不接触寄存器

### 3.2 App 层三个模块的职责

| 模块 | 职责 | 特点 |
|------|------|------|
| `app_knob.c` | 控制循环、状态机、蜂鸣器事件、ISR | 有状态的编排层 |
| `app_knob_physics.c` | 卡位数学计算 | 无状态的纯函数库 |
| `app_knob_limit.c` | 角度限位检测和弹簧力计算 | 独立子状态机 |
| `app_mode.c` | 控制模式状态 + 按钮业务逻辑 | 与力反馈完全解耦 |

**为什么这样拆分？**
- `physics` 和 `limit` 是**纯计算模块**——输入传感器数据，输出力指令，没有外部依赖
- `app_knob` 是**编排层**——协调各模块，管理状态转换，处理事件
- `app_mode` 是**独立状态模块**——只管控制模式，不碰力反馈

## 4. 数据结构设计

所有共享类型定义在 `App/Inc/app_knob.h` 中。

### 4.1 KnobPreset_t（预设方案）

```c
typedef enum
{
    KNOB_PRESET_COARSE_6 = 0,   // 6 卡位/圈, 间距 60°
    KNOB_PRESET_NORMAL_12,      // 12 卡位/圈, 间距 30°
    KNOB_PRESET_FINE_24,        // 24 卡位/圈, 间距 15°
    KNOB_PRESET_DENSE_48,       // 48 卡位/圈, 间距 7.5°
    KNOB_PRESET_SMOOTH,         // 无卡位, 完全平滑
} KnobPreset_t;
```

**设计意图：** 用户不用理解底层 22 个参数，只需选择一个预设。每种预设的内部参数（死区大小、爬坡起点、力度基准等）是预先调优好的。

### 4.2 KnobConfig_t（运行时配置）

```c
typedef struct
{
    KnobPreset_t preset;        // 预设方案
    uint8_t detent_strength;    // 卡位力度 (1-10)
    uint8_t return_strength;    // 归中力度 (1-10)
} KnobConfig_t;
```

**设计意图：** 3 个参数就能完全控制手感。`detent_strength` 影响转动时的阻力感，`return_strength` 影响松手后的归中速度。

### 4.3 KnobSensorData_t（传感器数据包）

```c
typedef struct
{
    float   angle;              // 当前角度 (°)，可累积超过 360°
    float   velocity;           // 角速度 (°/ms)，本 tick 角度 - 上 tick 角度
    int32_t raw_count;          // 原始编码器计数（调试用）
} KnobSensorData_t;
```

**设计意图：** 将每次 1ms 采样的数据打包，避免多个参数传递。

### 4.4 KnobForceOutput_t（力输出指令）

```c
typedef struct
{
    Knob_Motor_Dir_t direction; // 电机方向
    uint8_t duty_pct;           // PWM 占空比 (0-100)
} KnobForceOutput_t;
```

**设计意图：** 模块间传递"力"的指令。各模块计算自己想要的方向和占空比，控制循环汇总决定最终输出。

### 4.5 KnobState_t（工作状态）

```c
typedef enum
{
    KNOB_STATE_FREE = 0,        // 自由模式：正常转动，有卡位阻力
    KNOB_STATE_RETURNING,       // 归中模式：松手后电机推向卡位中心
    KNOB_STATE_LIMIT_BOUNCE,    // 限位弹跳：越界后的弹簧推回
} KnobState_t;
```

## 5. 控制循环详解

### 5.1 触发源：TIM3 1kHz 中断

```
文件：app_knob.c，函数 HAL_TIM_PeriodElapsedCallback()
```

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM3)
    {
        App_Knob_Control();  // 每 1ms 执行一次
    }
}
```

TIM3 配置：72MHz / (71+1) / (999+1) = 1000Hz = 1kHz。

### 5.2 主控制循环：App_Knob_Control()

```
文件：app_knob.c，函数 App_Knob_Control()
```

**8 步流水线：**

```
读传感器 ─→ 限位检测 ─→ 状态机计算力 ─→ 限位覆盖 ─→ 输出电机 ─→ 蜂鸣器 tick ─→ 卡位检测 ─→ 按键扫描
   │            │            │            │            │            │            │            │
 编码器      KnobLimit   switch(state)  限位激活时   PWM 输出   脉冲计时      detent 变化   控制模式
 读角度      _Update()   HandleXxx()    覆盖输出    到 TB6612  自动关断     触发蜂鸣      按键切换
```

**第 8 步说明**：按键扫描（`AppMode_ScanButtons`）放在 1kHz 循环里，
保证实时响应，不受主循环 `HAL_Delay(1000)` 阻塞影响（详见控制模式篇）。

**为什么限位在第 2 步检测，却在第 4 步覆盖？**

限位检测（第 2 步）可能触发状态切换到 `LIMIT_BOUNCE`，影响第 3 步状态机的行为。但无论状态机算出什么力，只要限位激活，第 4 步就用限位的弹簧力覆盖它——**限位优先级最高**。

### 5.3 卡位检测为什么在限位激活时跳过？

```c
// App_Knob_Control() 第 7 步：卡位检测 + 蜂鸣器触发
if (!KnobLimit_IsActive())
{
    s_current_detent = KnobPhysics_GetDetentIndex(s_current_sensor.angle);
    if (s_current_detent != s_last_detent)   // 使蜂鸣器在同一个卡位点不会持续响
    {
        s_last_detent = s_current_detent;
        if (s_buzzer_enabled)                // 蜂鸣器开关（上位机 SET_BUZZER 控制）
        {
            BSP_KnobBuzzer_Click();
        }
    }
}
```

限位弹跳时，旋钮在边界上来回振荡，卡位编号会快速变化。如果不冻结，蜂鸣器会连续响，体验很差。所以限位激活时，**卡位检测和蜂鸣器一起冻结**。

**蜂鸣器开关**：`s_buzzer_enabled` 默认开启，由上位机 `SET_BUZZER` 命令远程控制；关闭时卡位/限位蜂鸣均静音。

## 6. 状态机详解

### 6.1 三种状态与转换

```
                   连续静止 20ms
    ┌──────────┐ ───────────────→ ┌────────────┐
    │   FREE   │                  │ RETURNING  │
    │ 自由模式  │ ←─────────────── │  归中模式   │
    └─────┬────┘   进入死区 或     └────────────┘
          │        反向拧动
          │ 越界
          ▼
    ┌──────────┐   振荡稳定
    │  LIMIT   │ ──────────────→ 回到 FREE
    │  BOUNCE  │
    │ 限位弹跳  │
    └──────────┘
```

### 6.2 FREE 状态（HandleFreeState）

```
文件：app_knob.c，函数 HandleFreeState()
```

**五层判断（优先级从高到低）：**

```
1. 在死区内？
   └→ 是：电机 STOP，return（旋钮"卡"在卡位上，不施加任何力）

2. 几乎静止？（速度 < 0.18°/ms）
   └→ 是：s_still_count++，累计 20ms → 切换到 RETURNING
   └→ 否：s_still_count = 0

3. 未到爬坡区？（距离卡位中心 < bump_start）
   └→ 是：电机 STOP，自由滑行

4. 已过中点？（转动方向远离卡位中心）
   └→ 是：电机 STOP，滑向下一卡位

5. 在爬坡区 + 接近中点
   └→ 计算逆向阻力，抵抗转动方向
```

**爬坡阻力的直观理解：**

想象旋钮在两个卡位之间的"山峰"上。从山脚（bump_start）到山顶（half_spacing），越接近山顶阻力越大。翻过山顶后阻力消失，滑入下一个卡位的山谷（死区）。

```
     阻力方向 ←─┐              ┌─ 阻力方向
                │              │
       ╲        │   山顶       │        ╱
        ╲       │  (卡位中点)  │       ╱
         ╲      ▼              ▼      ╱
          ╲        自由滑行          ╱
     ─────◊──────────────────────◊─────
     死区  bump_start         bump_start  死区
    (卡位)                            (下一卡位)
```

### 6.3 RETURNING 状态（HandleReturningState）

```
文件：app_knob.c，函数 HandleReturningState()
```

**三个退出条件：**

1. **进入死区** → 归中完成，切回 FREE
2. **反向拧动** → 用户想往反方向转（速度 > 0.05°/ms 且方向远离目标），人手接管，切回 FREE
3. **其他情况** → 持续输出归中力（方向指向卡位中心，大小与距离成正比）

```c
// 检测"反向拧动"
int moving_away = (error > 0.0f && sensor->velocity < -REGRAB_VEL)  // 目标在前但向后转
               || (error < 0.0f && sensor->velocity >  REGRAB_VEL); // 目标在后但向前转
```

**设计意图：** 如果用户重新握住旋钮主动转动，应该立刻退出归中模式让用户自由操作。

### 6.4 LIMIT_BOUNCE 状态（HandleLimitBounceState）

```c
output->direction = KNOB_MOTOR_DIR_STOP;
output->duty_pct = 0;
```

状态机在弹跳状态**不输出任何力**，完全交给限位模块控制。限位模块会在振荡稳定后调用 `AppKnob_OnLimitExit()` 退出。

## 7. 卡位物理模型

```
文件：App/Src/app_knob_physics.c
```

### 7.1 预设参数表

**结构体：**
```c
typedef struct
{
    uint8_t num_detents;        // 每圈卡位数
    float   detent_angle;       // 卡位间距 (°)
    float   half_spacing;       // 半间距 (°)
    float   dead_zone;          // 死区 (°)
    float   bump_start;         // 爬坡起点 (°)
    float   bump_max_base;      // 基础爬坡力 (%)
    float   return_force_base;  // 基础归中力 (%)
} PresetParams_t;
```

**预设表（硬编码，已调优）：**

| 预设 | 卡位数 | 间距 | 死区 | 爬坡起点 | 爬坡力 | 归中力 |
|------|--------|------|------|----------|--------|--------|
| COARSE_6 | 6 | 60° | 3.9° | 21.0° | 22% | 24% |
| NORMAL_12 | 12 | 30° | 2.0° | 10.5° | 20% | 22% |
| FINE_24 | 24 | 15° | 1.0° | 5.3° | 16% | 18% |
| DENSE_48 | 48 | 7.5° | 0.6° | 2.6° | 12% | 14% |
| SMOOTH | 0 | — | — | — | 0% | 0% |

**设计原则：**
- 卡位越少（间距越大）→ 力度越强（防止手感太松）
- 卡位越多（间距越小）→ 力度越弱（防止太卡顿）
- 死区 ≈ 半间距 × 13%，最小 0.6°
- 爬坡起点 ≈ 半间距 × 70%

### 7.2 力度缩放

```
文件：app_knob_physics.c，函数 KnobPhysics_Init()
```

```c
float detent_mult = (float)detent_strength / 10.0f;   // 1→0.1, 10→1.0
float return_mult = (float)return_strength / 10.0f;   // 1→0.1, 10→1.0

s_bump_max_pct    = s_params.bump_max_base    * detent_mult;
s_return_force_pct = s_params.return_force_base * return_mult;
```

`detent_strength=1` 时，实际力 = 基础值 × 0.1（最轻）。`detent_strength=10` 时，实际力 = 基础值 × 1.0（最重）。

### 7.3 爬坡力计算

```
文件：app_knob_physics.c，函数 KnobPhysics_CalcBumpForce()
```

```c
// ramp = 0 (在 bump_start 位置) ～ 1 (在 half_spacing 位置)
float ramp_range = half_spacing - bump_start;
float ramp = (abs_err - bump_start) / ramp_range;

output.duty_pct = s_bump_max_pct * ramp;

// 阻力方向 = 与转动方向相反
if (velocity > 0) → REVERSE;   // 正转时施加反转力
else              → FORWARD;   // 反转时施加正转力
```

**关键公式：** 力 = 基础力 × strength_mult × (当前位置 - 爬坡起点) / (半间距 - 爬坡起点)

### 7.4 归中力计算

```
文件：app_knob_physics.c，函数 KnobPhysics_CalcReturnForce()
```

```c
float ratio = abs_err / half_spacing;    // 距中心越远，力越大
float force = s_return_force_pct * ratio;

if (force < s_return_force_floor)         // 地板值 = 基础值 × 0.7，最小 12%
    force = s_return_force_floor;

// 推力方向 = 指向卡位中心
if (error > 0) → FORWARD;   // 目标在正前方，向前推
else           → REVERSE;   // 目标在后方，向后推
```

**为什么有地板值？**

N20 减速箱有静摩擦，PWM < 12% 时电机根本推不动。地板值确保归中力至少能克服静摩擦。

### 7.5 关键判断函数

| 函数 | 判据 | 返回值 |
|------|------|--------|
| `IsInDeadZone` | abs_err < dead_zone | 1 = 在死区 |
| `IsInBumpZone` | abs_err >= bump_start | 1 = 在爬坡区 |
| `IsApproaching` | velocity 方向与 error 方向一致 | 1 = 正在接近中点 |
| `FindNearestDetent` | 四舍五入到最近 detent_angle 倍数 | 卡位中心角度 |
| `GetDetentIndex` | 最近卡位 / detent_angle | 卡位编号 |

## 8. 角度限位模块

```
文件：App/Src/app_knob_limit.c
```

### 8.1 三种模式

```c
typedef enum
{
    KNOB_LIMIT_MODE_OFF = 0,    // 关闭限位
    KNOB_LIMIT_MODE_SINGLE,     // 仅上限
    KNOB_LIMIT_MODE_DUAL,       // 上下限均有效（默认）
} Knob_LimitMode_t;
```

### 8.2 弹簧-阻尼模型

```
文件：app_knob_limit.c，函数 KnobLimit_Update() 的弹簧-阻尼段
```

```c
float spring = abs_err * spring_kp;      // 弹簧力 = 距边界距离 × 刚度
float damp   = abs_vel * spring_kd;      // 阻尼力 = 速度 × 阻尼系数
float force  = spring - damp;            // 合力 = 弹簧 - 阻尼
```

**物理直觉：**
- 越界越远 → **弹簧力越大**（推回边界）
- 速度越快 → **阻尼力越大**（防止振荡）
- `spring_kp` 越大 → 边界越"硬"
- `spring_kd` 越大 → 振荡衰减越快

### 8.3 去抖机制

```
文件：app_knob_limit.c 第 93、109 行
```

```c
if (s_debounce_count == 0)
{
    AppKnob_OnLimitEnter();           // 触发蜂鸣 + 状态切换
    s_debounce_count = LIMIT_DEBOUNCE_MS;  // 100ms 内不再触发
}
```

**为什么需要去抖？**

越过边界时，弹簧推回导致旋钮可能在边界附近快速来回振荡。如果每次越过都触发蜂鸣，会连续响。100ms 去抖保证蜂鸣只响一声。

### 8.4 振荡稳定检测

```
文件：app_knob_limit.c，函数 KnobLimit_Update() 的振荡稳定段
```

```c
if (abs_err < LIMIT_SETTLE_ANGLE && abs_vel < LIMIT_SETTLE_VEL)
{
    s_settle_count++;
    if (s_settle_count >= LIMIT_SETTLE_MS)  // 连续稳定 50ms
    {
        s_bounce_active = 0;
        AppKnob_OnLimitExit();      // 退出限位弹跳
    }
}
```

**设计意图：** 不是"角度回到边界内"就立刻退出，而是等振荡停下来（位置和速度都接近零）后再退出，避免反复触发。

## 9. 蜂鸣器与事件

### 9.1 触发时机

| 事件 | 触发位置 | 说明 |
|------|----------|------|
| 跨过卡位 | `App_Knob_Control()` 第 7 步 | 卡位编号变化时（受蜂鸣器开关控制） |
| 撞击限位 | `AppKnob_OnLimitEnter()` | 越界进入弹跳时（受蜂鸣器开关控制） |

### 9.2 脉冲管理

```c
BSP_KnobBuzzer_Click();   // 触发 5ms 低电平脉冲 + 50ms 冷却
BSP_KnobBuzzer_Tick();    // 每 1ms 调用，管理脉冲计时和自动关断
```

`Tick()` 在控制循环第 6 步每 1ms 执行，内部用计数器控制脉冲宽度（`BUZZER_ON_MS = 5`）。
`Click()` 触发后进入 `BUZZER_COOLDOWN = 50` 的冷却期，冷却期内再次调用会被直接忽略，
防止高密度卡位切换或边界振荡时听起来像长鸣。

### 9.3 冻结合并

限位激活时，卡位检测被跳过（`App_Knob_Control()` 第 7 步的 `if (!KnobLimit_IsActive())`），避免边界振荡时蜂鸣器误触发。这与限位模块的去抖（100ms）是**双重保护**。

### 10.4 常见调优建议

| 问题 | 可能原因 | 调整方向 |
|------|----------|----------|
| 卡位太松，没感觉 | 爬坡力不够 | 增大 `detent_strength` 或换更粗的预设 |
| 卡位太硬，拧不动 | 爬坡力太大 | 减小 `detent_strength` |
| 归中太慢 | 归中力太小 | 增大 `return_strength` |
| 归中后来回摆 | 归中力太大 | 减小 `return_strength` |
| 限位太软 | 弹簧刚度不够 | 增大 `SPRING_KP` |
| 限位撞后一直振荡 | 阻尼不够或去抖太短 | 增大 `SPRING_KD` 或 `DEBOUNCE_MS` |
| 蜂鸣器连响 | 去抖时间不够 | 增大 `LIMIT_DEBOUNCE_MS` |
| 电机不转 | STBY 没拉高或 PWM 占空比太低 | 检查 PB9，确认 `return_force_floor >= 12` |
