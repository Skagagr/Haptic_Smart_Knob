# 项目交接文档 — Haptic Smart Knob

> 本文件用于上下文压缩后快速恢复项目状态。包含：当前进度、架构、协议、已知问题、下一步计划。

## 项目概况

力反馈智能旋钮：STM32F103C8T6 驱动 N20 减速电机，模拟卡位手感；USB-CDC 与 C# WinForms 上位机双向通信，控制电脑音量和亮度。

**两个子项目**（平行目录）：
- `Haptic_Smart_Knob/` — STM32 固件（CMake + arm-none-eabi，CubeMX 生成）
- `Haptic_Knob_Host/` — C# WinForms 上位机（.NET 8，VS 2022）

### 协议命令表
| 命令 | Type | 载荷 | 说明 |
|------|------|------|------|
| SET_CONFIG | 0x02 | 1B preset(0-4) | 设置预设 |
| GET_ANGLE | 0x03 | 空 | 查角度(4B float LE) |
| SET_LIMIT_MODE | 0x04 | 1B (0关/1单/2双) | 限位模式 |
| GET_STATE | 0x07 | 空 | 返回 [模式1B][角度4B] |
| SET_MODE | 0x08 | 1B (0空闲/1音量/2亮度) | 同步控制模式 |
| SET_BUZZER | 0x09 | 1B (0关/1开) | 蜂鸣器开关 |

响应 = 命令\|0x80，载荷首字节状态码（0=OK）。上位机 50ms 轮询 `GET_STATE`。

## 固件架构（Haptic_Smart_Knob/）

```
App/Src/
├── app_knob.c           # 1kHz 控制循环 + 状态机（8 步：读传感器→限位→状态机→输出→蜂鸣→卡位检测→按键扫描）
├── app_knob_physics.c   # 卡位物理（纯计算）
├── app_knob_limit.c     # 限位弹簧+阻尼
├── app_mode.c           # 控制模式状态 + 按钮业务逻辑
└── app_usb_protocol.c   # 帧解析 + CRC8 + 命令分发
Drivers/BSP/
├── Knob_Motor/          # N20 + TB6612
├── Knob_Encoder/        # TIM2 编码器
├── Knob_Buzzer/         # 蜂鸣器
└── Knob_Indicator/      # LED + 按键扫描（映射表+消抖+边沿检测）
```

- 按键扫描在 `App_Knob_Control()` 第 8 步（1kHz ISR），不受主循环 `HAL_Delay(1000)` 阻塞
- 新 BSP 目录需在 `CMakeLists.txt` 的 GLOB 和 include 各加一行
- FLASH 占用：约 94.43%（61.9KB/64KB），RAM 40.98%

## 上位机架构（Haptic_Knob_Host/）

```
Form1.cs                  # 主窗口：串口选择/轮询/预设/音量亮度/模式/蜂鸣器
Form1.Designer.cs         # 控件布局（手动维护，VS 设计器可见）
Protocol/KnobProtocol.cs  # CRC8 + 帧构建 + 解析状态机 + 命令封装
Volume/VolumeController.cs     # NAudio CoreAudio
Volume/BrightnessController.cs # WMI，后台节流写入
```

- `KnobControlMode` 枚举在协议层（None/Volume/Brightness），与固件 KnobStateMode_t 值对齐
- 模式互斥：勾音量自动取消亮度（`_syncingMode` 防轮询同步死循环）
- 轮询 `GET_STATE` → `SyncModeFromFirmware` 同步复选框；勾选 → `ApplyModeChange` 发 `SET_MODE`

## 关键调试信息

- 旋钮 USB 串口：COM7（上位机下拉框选择）
- 上位机用 `dotnet build`（在 Haptic_Knob_Host/ 目录）；固件用 `cmake --build --preset Debug`
- Flash 分析脚本：`Haptic_Smart_Knob/flash_size.ps1`（解析 .map 按文件统计）
- 亮度 WMI 台式机外接屏可能不支持（返回 -1）

## 下一步计划（重点）

### 旋钮伺服跟随（"PC 变 → 旋钮跟转"）
用户已确认方向，尚未开始。需要：
1. **固件**：新增闭环位置环（PID 或 P 控制）——接收目标角度，驱动电机转到该角度
   - **人手接管检测**：用户握住/转动旋钮时，检测到异常力矩或速度冲突 → 退出伺服、交还手动控制
   - 新命令：`SET_TARGET_ANGLE`（设目标角度）之类
2. **上位机**：音量/亮度变化时（如拖滑块、系统音量被改）下发目标角度
   - 角度与音量映射：音量 0~100 → 角度（需定映射关系，如一圈 360°=0~100）
3. 与现有"控制模式"（无限旋转）共存：伺服模式下应恢复限位或禁用？

### 设计要点
- 伺服跟随与卡位手感冲突：跟随到目标角度时是否还要卡位？大概率需要**单独伺服模式**（类似现有控制模式枚举扩展）
- 人手接管是难点：N20 电机怎么感知"被手握住"——力矩估算（电流/占空比）或速度/位置误差检测
